# Qt UI Design Skill（中文版）

## 适用场景

当用户要求设计 Qt 界面、优化 QML UI、从原型/截图实现界面、改进可用性、检查视觉和交互质量时使用。

## 两阶段流程

### 阶段 1：设计前澄清

在创建 UI 前确认：

1. 目标平台：桌面、移动、Web、嵌入式、MCU 或特定硬件。
2. 用户是谁：医生、护士、工程师、操作员、普通用户等。
3. 核心任务：用户最常做什么，最怕出错什么。
4. 输入输出：数据来自哪里，用户操作后产生什么。
5. 安全/风险：误触、报警、权限、医疗/工业场景风险。
6. 视觉约束：品牌、主题、现有设计系统、暗色/亮色。
7. 技术约束：Qt 版本、控件库、硬件性能、触控/键鼠。

### 阶段 2：设计与实现约束

设计时应用：

- 明确视觉层级。
- 关键动作可见且可达。
- 交互状态完整：normal、hover、pressed、focus、disabled、error、loading。
- 文本清晰，避免被截断或重叠。
- 支持键盘导航和焦点指示。
- 支持高 DPI / 字体缩放。
- 避免无意义装饰，尤其在工具型、医疗、工业界面中。

## Qt/QML 实现建议

- 优先使用 Qt Quick Controls。
- 自定义控件时设置 `background`、`contentItem`、`indicator` 等。
- 对触控界面保证足够点击目标。
- 对桌面工具界面保证信息密度和扫描效率。
- 对报警/安全信息至少提供颜色以外的第二提示，例如文字、图标或形状。
- 不要只靠颜色表达状态。

## 嵌入式 / MCU 注意事项

- 固定像素布局可能比响应式布局更合适。
- 控制动画和 GPU 成本。
- 避免复杂 shader、粒子和频繁 Canvas 重绘。
- 字体、图片和图标资源要考虑内存。
- 触控目标通常需要更大尺寸。

## 可访问性

- 自定义交互组件设置 `Accessible.role` / `Accessible.name`。
- Tab 顺序符合视觉阅读顺序。
- 焦点状态清晰可见。
- 警告和错误信息不要只依赖颜色。

## 输出要求

输出应包含：

- 设计目标和目标用户。
- 关键任务流。
- UI 结构和组件分解。
- 交互状态。
- 可访问性与风险控制。
- QML 实现注意事项。
- 验证清单。

## 验证清单

- 文本无重叠、无截断。
- 关键操作易发现。
- 禁用、加载、错误状态完整。
- 键盘可达。
- 高 DPI / 字体缩放下仍可用。
- 视觉层级服务于任务，而不是装饰。
- 性能预算与目标硬件匹配。
