# QML 文档 Skill（中文版）

## 适用场景

当用户要求为 QML 文件、组件、模块或 API 生成/更新开发文档时使用。

## 文档原则

- 先阅读代码和项目约定，再写文档。
- 文档面向后续维护者，不是给最终用户的功能介绍。
- 解释组件在项目中的角色、何时使用、解决什么问题。
- 不编造不存在的属性、信号或行为。
- 保留实际 API 名称，避免翻译代码标识符。

## 推荐结构

### 概览

说明组件做什么、属于哪个模块、在界面或逻辑中扮演什么角色。

### 何时使用

说明调用方在什么场景下应该使用该组件。

### Public API

列出外部可设置或可调用的内容：

- `property`
- `required property`
- `property alias`
- `signal`
- public function

每个条目说明类型、含义、默认值和使用约束。

### 行为

描述组件主要状态、交互、生命周期、加载策略、数据流。

### 示例

给出最小可运行或最小可理解示例，避免无关装饰。

### 注意事项

记录已知限制、性能注意、可访问性、国际化、与 C++ 集成约束。

## 输出要求

- 使用清晰 Markdown。
- 不重复源码内容。
- 不把内部实现细节伪装成公共 API。
- 对复杂组件说明数据流和状态变化。
- 如果发现代码缺少必要 API 或命名不清，可在文档末尾列出“建议改进”。
